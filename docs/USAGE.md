# 使用手册

本文面向**使用者**，介绍从注册登录到日常收信、子地址管理、一邮多用和管理后台的完整操作。部署方法见 [DEPLOYMENT.md](DEPLOYMENT.md)，接口细节见 [API.md](API.md)。

文中以 `example.com` 作为邮箱域名示例，实际使用时替换成你部署的域名。

---

## 1. 注册与登录

### 1.1 打开站点

浏览器访问部署好的地址，例如 `https://mail.example.com/`。手机浏览器同样可用，页面会自动切换为单栏布局。

### 1.2 注册账号

1. 切换到「注册」标签。
2. 填写你的常用邮箱（默认要求 QQ 邮箱 / Foxmail / 腾讯企业邮，管理员可以关闭限制）。
3. 点击「验证这个邮箱」：
   - 站点配置了发信通道（Resend）时，会直接发送 6 位验证码；
   - 未配置发信通道时，页面会给出一个 `verify-xxxx@example.com` 地址，用你的邮箱给这个地址发一封空邮件即可完成验证。
4. 输入验证码。
5. 设置密码（至少 8 位）。
6. 填写想要的邮箱名，例如 `bili`，系统自动拼成 `bili@example.com`。
7. 手机号可选，仅做格式与唯一性校验（短信验证需要管理员另行接入）。
8. 提交后自动登录。

> 一个普通账号只能有一个主邮箱。需要更多地址时，用主邮箱下的**子地址**，不需要重复注册。

### 1.3 登录

在「登录」标签填写**注册邮箱**（QQ 邮箱等）和密码。登录状态默认保持 30 天。

登录失败次数过多会触发限流：同一 `IP + 邮箱` 在 15 分钟内失败 20 次会暂时返回 429。

### 1.4 忘记密码

1. 登录页点击「忘记密码？」
2. 填写注册邮箱，获取 6 位验证码；
3. 输入验证码和新密码；
4. 提交后所有旧会话立即失效，需要重新登录。

> 如果站点未配置发信通道，自助找回不可用，需要管理员在后台重置密码。

## 2. 主邮箱与子地址

### 2.1 核心模型

```
一个账号
└── 一个主邮箱 bili@example.com
    ├── bili1@example.com          （数字后缀）
    ├── bili2024@example.com       （数字后缀）
    ├── bili-shop@example.com      （短横线）
    ├── bili.taobao@example.com    （点）
    ├── bili_github@example.com    （下划线）
    └── bili+x@example.com         （加号）
```

以上所有地址的信都会进入 `bili` 的同一个收件箱。侧栏会把子地址折叠在主邮箱下面，点主邮箱看全部，点子地址只看该来源的邮件。

### 2.2 匹配规则

| 收件人 | 是否属于主邮箱 `bili` |
| --- | --- |
| `bili@example.com` | 主地址本身 |
| `bili1@`、`bili2024@` | ✅ 纯数字后缀 |
| `bili-shop@`、`bili.taobao@`、`bili_x@`、`bili+x@` | ✅ 分隔符后缀 |
| `bilibili@` | ❌ 前缀相同但剩余部分不是数字、也不以分隔符开头 |
| `bili2x@` | ❌ 剩余部分 `2x` 不符合规则 |

注册新邮箱名时，系统会检查「名字吞并」冲突：已有 `bili` 时不能注册 `bili1` 作为主邮箱，反之亦然。

### 2.3 手动新建子地址

左侧「新建邮箱」→ 选择「子地址」→ 填 `shop` → 得到 `bili-shop@example.com`。

手动创建的子地址会一直显示在侧栏，即使还没有收到邮件。不需要时鼠标移到该子地址上点 `×` 删除；已收到的邮件保留，之后发往该地址的邮件会被拒收。

### 2.4 自动登记

默认开启「子地址自动归并」：某个子地址第一次收到信时会自动出现在侧栏。管理员可以在后台关闭该功能；关闭后未登记的子地址来信会被丢弃，并在「被丢弃的信」中记录。

## 3. 日常收信

| 我想…… | 操作 |
| --- | --- |
| 复制主地址 | 阅读区顶部的复制按钮，或左侧主邮箱行右侧图标 |
| 只看某个子地址的邮件 | 点击左侧折叠列表中的子地址；点主邮箱回到全部 |
| 搜索邮件 | 顶部搜索框，支持发件人、主题、正文摘要 |
| 阅读邮件 | 点击列表中的邮件，右侧显示内容；HTML 邮件在沙箱 iframe 中渲染 |
| 下载附件 | 邮件上方附件条，点击直接下载，中文文件名正常 |
| 下载原始邮件 | 阅读区右上角下载按钮，得到 `.eml` 文件 |
| 全部标为已读 | 列表右上角「全部已读」，只影响当前筛选 |
| 删除邮件 | 阅读区右上角删除按钮 |
| 修改昵称 / 密码 | 右上角齿轮 →「账号设置」 |
| 换绑手机号 | 账号设置 → 手机号 →「换绑」，需输入当前密码 |
| 换绑登录邮箱 | 账号设置 → 登录邮箱 →「换绑」，需验证新邮箱并输入当前密码 |

### 3.1 邮件大小与附件限制

- 单封邮件最大 25 MB（本机版由 `config.json` 的 `maxSizeMB` 控制）。
- Cloudflare D1 单行上限 1 MB，因此**超过约 900 KB 的附件不会保存**，邮件正文和其他内容仍会保存。
- 邮件默认永久保留；管理员可设置自动清理天数，`0` 表示永久保留。

### 3.2 未登记地址

发往「谁都没注册过」的地址（例如 `nobody@example.com`）默认进入 root 的「未登记地址」收件箱，列表会显示真实收件地址，方便临时收验证码。

root 可以在管理后台关闭此功能；关闭后被丢弃的邮件会记录在「被丢弃的信」列表中，包含发件人、收件地址、主题和时间。

## 4. 一邮多用：把外部邮箱的信收进来

「一邮多用」通过**自动转发**把 QQ、Gmail、163 等邮箱的来信汇聚到本站，不需要把外部邮箱密码交给本站。

### 4.1 添加外部邮箱

1. 左侧「一邮多用」→「+ 接入」。
2. 选择邮箱类型（QQ / Foxmail / Gmail / 163 / 126 / 腾讯企业邮 / Outlook / iCloud / 其他）。
3. 填写外部邮箱地址和备注（可选）。
4. 系统生成专属入口地址，例如 `bili-qq@example.com`。
5. 到外部邮箱开启「自动转发」，把收件人设为该入口地址。
6. 外部邮箱会发一封确认邮件到入口地址，在收件箱中打开并确认即可。

### 4.2 各邮箱的转发入口

| 邮箱 | 设置位置 |
| --- | --- |
| QQ 邮箱 / Foxmail | 设置 → 账户 → 自动转发 → 添加收件人 |
| Gmail | 设置 → 转发和 POP/IMAP → 添加转发地址 → 确认 |
| 网易 163 / 126 | 设置 → 自动转发 / 邮件转移 |
| 腾讯企业邮 | 设置 → 邮件转移 |
| Outlook / iCloud | 设置 → 邮件 → 转发 |
| 其他 | 查找「自动转发」，指向入口地址 |

### 4.3 来源标签与筛选

转发来的邮件会带 `QQ`、`Gmail` 等小标签，读信区显示「来自外部邮箱」。入口地址挂在主邮箱下面，点击可只看该来源的邮件。

删除某个接入后，该入口地址立刻拒收新邮件，已收到的邮件保留。

> 原理是**转发**而不是 IMAP 代收：Cloudflare Workers 无法维持长连接 IMAP，也避免保存外部邮箱密码。

## 5. 账号设置

右上角齿轮打开「账号设置」：

- **昵称**：显示在界面右上角，最多 24 个字符。
- **手机号**：可选，11 位中国大陆号码；换绑需输入当前密码，留空可解绑。
- **登录邮箱**：换绑需要先验证新邮箱（验证码或确认邮件），再输入当前密码。
- **修改密码**：至少 8 位，修改后其他设备上的旧会话仍然有效，除非管理员重置密码。

## 6. 管理后台（root / 管理员）

root 登录后，右上角出现盾牌图标，点击进入管理后台。管理员也可以进入，但部分针对 root 的操作会被禁止。

### 6.1 概览

显示用户数、主邮箱数、邮件数、未读数、占用空间、域名数、在线会话，以及最近的「被丢弃的信」。

### 6.2 用户管理

- 搜索：按邮箱、手机号、昵称模糊搜索。
- 停用 / 启用：停用会立即清除该用户所有会话。
- 设为管理员 / 取消管理员。
- 重置密码：生成 10 位临时密码并让该用户所有会话失效。
- 删除用户：级联删除其邮箱、子地址、邮件、附件和会话。

限制：管理员不能停用或删除自己，不能修改 root 的角色，不能删除 root；root 的密码只能由 root 自己修改。

### 6.3 域名管理

- 添加域名：域名必须已在同一 Cloudflare 账号下开通 Email Routing 并指向本 Worker。
- 删除域名：会连带删除该域名下所有邮箱、子地址和邮件，操作不可恢复。
- 修改备注：仅用于标记用途。

### 6.4 全局开关

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| 子地址自动归并 | 开 | 未登记子地址首次来信时自动登记 |
| 未登记地址进 root 收件箱 | 开 | 关闭后陌生地址来信直接丢弃并记录 |
| 注册限 QQ 邮箱 | 开 | 关闭后任意邮箱均可注册 |
| 短信验证 | 关 | 预留开关，接入短信服务后才生效 |
| 自动清理天数 | 0 | 大于 0 时按天数清理旧邮件，0 为永久保留 |

## 7. 多域名

一个 Worker 可以同时服务多个域名。添加新域名：

1. 域名接入同一个 Cloudflare 账号；
2. 为该域名开启 Email Routing；
3. Catch-all 指向同一个 Worker；
4. 在管理后台 → 域名 → 添加该域名；
5. 用户注册时即可从下拉列表选择该域名作为邮箱后缀。

每个域名下的邮箱、子地址和邮件彼此独立，但共享同一个用户体系。

## 8. 常见问题

**Q：网页能打开，但一直收不到信？**

1. 确认 Cloudflare Email Routing 状态为 Ready；
2. 确认 Catch-all 指向了正确的 Worker；
3. 确认 Worker 已设置 `ACCESS_TOKEN`；
4. 确认 D1 绑定变量名为 `DB`；
5. 查看 Cloudflare Worker 的实时日志；
6. 用 `node test/check-dns.mjs 你的域名` 检查 MX/SPF。

**Q：发信被退回 550？**

收件地址没有注册，或该子地址被删除 / 被管理员关闭自动归并。检查后台「被丢弃的信」。

**Q：注册时提示只支持 QQ 邮箱？**

管理员开启了 `requireQQ`。使用 QQ / Foxmail / 腾讯企业邮注册，或请管理员关闭该开关。

**Q：收不到某网站的验证码？**

先检查「未登记地址」箱；如果那里也没有，可能是对方不向该域名发信（部分站点会屏蔽新域名），或 DNS 缓存尚未过期。

**Q：能发信吗？**

默认只收不发。需要发信时接入 Resend 等 HTTP 发信服务；当前代码仅在注册验证码、找回密码等场景使用发信通道。

**Q：数据在哪里？如何备份？**

- 本机版：`data/mail.db`（SQLite），复制整个 `data/` 目录即完成备份。
- Cloudflare 版：数据在 D1，可在 Cloudflare 控制台导出。

**Q：忘记 root 密码怎么办？**

用部署时设置的 `ACCESS_TOKEN` 登录（它就是 root 初始密码）；或让另一个管理员在后台重置。修改网页密码不会改变 `ACCESS_TOKEN` 作为 `/api/ingest` 投递口令的用途。

**Q：邮件 HTML 里的图片不显示？**

远程图片可能被邮件客户端策略拦截，或原图需要登录。下载 `.eml` 后用本地邮件客户端打开可查看完整内容。
